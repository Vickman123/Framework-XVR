## 2. Auditoría Arquitectónica por Componente

### 2.1. `XRApp`
- **Responsabilidad**: Actúa como Fachada (*Facade Pattern*). Su trabajo es orquestar `XRScene`, `XRRenderer`, `XRSession` y `XRAssetManager`, así como enlazar los controles de órbita y la interacción por raycast.
- **Acoplamiento**:
  - *Alto pero justificado*: Conoce directamente a los 4 módulos internos. Es la puerta de entrada para el 90% de los usuarios.
  - *Problema detectado*: Inicializa `OrbitControls` directamente en el constructor. Si un desarrollador quisiera usar controles en primera persona (`PointerLockControls`) o controles personalizados, `OrbitControls` se crea innecesariamente a menos que pase `autoOrbitControls: false`.
- **Lifecycle**: Limpio. `start()` y `stop()` delegan en `renderer`. `dispose()` recorre y destruye en orden: controles, sesión, assets, escena y renderizador.

### 2.2. `XRScene`
- **Responsabilidad**: Configurar el entorno lumínico y visual por defecto para que un modelo no se vea negro ni sin sombras al cargar.
- **Relación con THREE.Scene**: No hereda de `THREE.Scene`, sino que la envuelve mediante composición (`public readonly nativeScene: THREE.Scene`). Esto es un acierto de diseño: permite usar métodos Three.js directamente mientras VXR gestiona luces y rejillas.
- **Puntos de atención**: Las luces `ambientLight`, `directionalLight` y `hemiLight` son públicas. Si el usuario las reemplaza o borra manualmente, `setEnvironmentPreset()` podría lanzar error por acceso a `null` si no valida existencia previa.

### 2.3. `XRRenderer`
- **Responsabilidad**: Encapsular el ciclo WebGL, configuración de cámara y bucle de render.
- **Gestión de Pixel Ratio**: Fija `Math.min(window.devicePixelRatio, pixelRatioCap)`. Es una decisión técnica óptima para Meta Quest y dispositivos móviles.
- **Shadows y Tone Mapping**: `ACESFilmicToneMapping` está fijado en el código fuente (*hard-coded*). En Meta Quest 2 / 3S, `LinearToneMapping` es sensiblemente más rápido. Debería ser configurable en las opciones.
- **WebXR Enabled**: Configura `nativeRenderer.xr.enabled = true` desde el arranque.

### 2.4. `XRSession`
- **Responsabilidad**: Negociar la sesión con el hardware WebXR, suministrar el botón "ENTER VR" y gestionar los rayos de los mandos.
- **Controllers & Raycasting**: Configura automáticamente 2 mandos con una línea visible (`VXR_LaserRay`) de 3 metros y añade `raycastController()`.
- **Puntos de atención**:
  - Actualmente asume espacio de referencia `local-floor`. Si el visor o navegador no soporta `local-floor`, no tiene fallback a `local`.
  - No expone aún `getHand(i)` para Hand Tracking nativo, aunque solicita la característica en `optionalFeatures`.
  - La línea del rayo láser tiene longitud fija (3m); no se acorta dinámicamente cuando colisiona con un objeto cercano.

### 2.5. `XRAssetManager`
- **Responsabilidad**: Carga asíncrona de modelos `.glb`/`.gltf`, normalización espacial y liberación de memoria.
- **Grounding y Centering**: Muy sólido. Calcula `THREE.Box3`, desplaza la escena interna para que su base esté en $Y = 0$ y centra en $X, Z$.
- **Cálculo de Métricas**: Extrae dimensiones reales, polígonos, vértices y recuento de mallas.
- **Disposal**: Recorre la jerarquía y llama a `geometry.dispose()`, `material.dispose()` y desecha texturas adjuntas (`map`, `normalMap`, etc.). Es un escudo contra fugas de memoria GPU en visores autónomos.

## 4. Análisis de los Tres Ejemplos de Validación

### Patrón 1: Detección de Colisión e Interacción Unificada
- **Aparición**: Presente en `Architecture Viewer` (selección de mallas) y en `XR Interaction Lab` (activación de instrumentos).
- **¿Es una abstracción?**: Sí. Ambos ejemplos necesitaron saber: "¿Qué objeto impactó el rayo y a qué distancia?".
- **Veredicto**: Pertenece al Core (`app.raycastPointer` y `app.raycastController`).

### Patrón 2: Memorización y Restauración de Materiales para Highlight
- **Aparición**: `Architecture Viewer` y `XR Interaction Lab` alteran el color o material de la malla bajo el puntero y deben restaurar el material previo al salir o deseleccionar.
- **¿Pertenece al Core?**: **NO.** El Core no debe decidir si el highlight es un tinte emisivo, una silueta (*outline*) o un bounding box.
- **Veredicto**: Candidato para un módulo satélite opcional (`@vxr/ui` o `@vxr/interaction`), nunca en `@vxr/core`.

### Patrón 3: Panel de Telemetría / HUD Contextual
- **Aparición**: Los tres ejemplos muestran métricas (dimensiones, polígonos, estado de instrumentos, log).
- **¿Pertenece al Core?**: **NO.** La interfaz visual es responsabilidad de la aplicación web o de un módulo de UI. El Core solo debe proveer los datos crudos (`LoadedModel.metrics`).

## 5. Auditoría de Relación con Three.js

```
┌─────────────────────────────────────────────────────────┐
│                       APLICACIÓN                        │
│    (Basic Viewer, Architecture Viewer, Interaction Lab)  │
└────────────────────────────┬────────────────────────────┘
                             │ consume
                             ▼
┌─────────────────────────────────────────────────────────┐
│                        VXR CORE                         │
│  - XRApp (Fachada)                                      │
│  - XRScene (Environment, Grounding, Disposal)           │
│  - XRRenderer (Resize, XR Loop, Camera)                 │
│  - XRSession (VRButton, Controllers, Raycasting)        │
│  - XRAssetManager (GLTF, DRACO, Metrics)                │
└────────────────────────────┬────────────────────────────┘
                             │ utiliza internamente y expone
                             ▼
┌─────────────────────────────────────────────────────────┐
│                        THREE.JS                         │
│  THREE.Scene • THREE.WebGLRenderer • THREE.Camera       │
│  THREE.Raycaster • THREE.Mesh • THREE.Material • Box3   │
└────────────────────────────┬────────────────────────────┘
                             │ consume hardware
                             ▼
┌─────────────────────────────────────────────────────────┐
│                      WEBXR DEVICE API                   │
└─────────────────────────────────────────────────────────┘
```

- **¿VXR oculta Three.js?**: **No.** VXR expone directamente:
  - `app.nativeScene` (`THREE.Scene`)
  - `app.nativeRenderer` (`THREE.WebGLRenderer`)
  - `app.camera` (`THREE.PerspectiveCamera`)
  - `model.group` (`THREE.Group`)
  - `model.rawGltf` (`GLTF`)
  - Retorna colecciones estándar de Three.js: `THREE.Intersection[]`.
- **Evaluación**: La relación es correcta y saludable. Un usuario avanzado puede añadir post-procesamiento, shaders personalizados (`ShaderMaterial`) o luces de Three.js sin restricciones.

## 6. Auditoría de Soporte WebXR

- **Sesión inmersiva**: Usa `navigator.xr.requestSession('immersive-vr')`. Correcto.
- **Espacio de referencia**: Configurado a `local-floor` con `bounded-floor` y `hand-tracking` opcionales.
- **Mandos y Rayos**: Crea `XRTargetRaySpace` para ambos índices (0 y 1) con líneas visuales y escucha `select`.
- **Lagunas detectadas**:
  1. *Falta de eventos para Grip*: Solo escucha `select` (gatillo). No escucha aún `squeezestart` / `squeezeend` (botón de agarre lateral).
  2. *Sin soporte visual de manos*: Aunque pide `hand-tracking` en `optionalFeatures`, no instancia `renderer.xr.getHand(i)`.
  3. *Tasa de refresco en Quest*: No solicita todavía `session.updateTargetFrameRate(72 | 90)`.

## 7. Rendimiento y Optimización para Meta Quest

### 7.1. Tabla de Parámetros: Hardcoded vs Configurable

| Parámetro | Estado en v0.1.0 | Evaluación | Recomendación v0.2 |
| :--- | :---: | :--- | :--- |
| `pixelRatioCap` | Configurable (Default: 1.5) | **Correcto**. Protege contra sobrecalentamiento en Quest y pantallas Retina. | Mantener configurable. |
| `precision` | Three.js default (`highp`) | **Requiere atención**. En chips Adreno móviles, `mediump` ahorra ciclos de fragment shader. | Añadir opción `precision: 'highp' \| 'mediump'`. |
| `toneMapping` | Hard-coded (`ACESFilmic`) | **Requiere atención**. En escenas complejas en Quest, `LinearToneMapping` es más rápido. | Hacer configurable en `XRAppOptions`. |
| `shadowMap.type` | Hard-coded (`PCFSoftShadowMap`) | **Correcto** para calidad visual desktop; puede ser pesado para Quest con muchos objetos. | Permitir desactivar o degradar a `BasicShadowMap`. |
| `frustumCulled` | Hard-coded (`true` en mallas cargadas) | **Excelente**. Descarta geometrías fuera del campo de visión automáticamente. | Mantener forzado en `XRAssetManager`. |
| `DRACOLoader` | Path por defecto a CDN de Google | **Correcto** para inicio rápido; permite path local personalizado. | Mantener. |

## 8. Auditoría de TypeScript

- **Tipado estricto**: `strict: true` activado en `tsconfig.base.json`. Compila con 0 errores y genera `.d.ts` y sourcemaps completos.
- **Nullability**: `model: LoadedModel | null`, `currentSession: XRSession | null`. Correcto.
- **Oportunidades de mejora detectadas**:
  - En `XRAssetManager.loadModel`, la promesa interna tipa `resolve(data: any)` en lugar de `GLTF`. Se debe tipar estrictamente con `import { GLTF } from 'three/examples/jsm/loaders/GLTFLoader.js'`.
  - El retorno de `onUpdate` y `onControllerSelect` devuelve `() => void` para desuscribirse limpiamente. Excelente patrón.

## 9. Architecture Scorecard

> Evaluación cualitativa según directrices: **Correcto**, **Requiere atención**, **Riesgo**, **Recomendado**, **Futuro**.

| Dimensión | Estado | Diagnóstico |
| :--- | :---: | :--- |
| **Arquitectura de Capas** | **Correcto** | Clara separación entre fachada (`XRApp`), subsistemas (`XRScene`, `XRRenderer`, `XRSession`, `XRAssetManager`) y Three.js. |
| **Ergonomía de API** | **Correcto** | El flujo de 3 líneas `new XRApp() -> loadModel() -> start()` es intuitivo y comprobado por los 3 ejemplos. |
| **Transparencia Three.js** | **Correcto** | Expone objetos nativos sin secuestrar ni ocultar las capacidades de Three.js. |
| **TypeScript & Tipos** | **Correcto** | Declaraciones `.d.ts` generadas, interfaces exportadas y contratos claros. |
| **Manejo de Memoria / Dispose** | **Correcto** | `XRAssetManager` y `XRScene` implementan rutinas agresivas de liberación de geometrías y texturas GPU. |
| **Controladores WebXR** | **Requiere atención** | Raycasting funcional, pero falta lectura de botones grip y soporte de longitud dinámica del rayo láser. |
| **Optimización Quest** | **Requiere atención** | `toneMapping` y `precision` deben ser configurables para exprimir el rendimiento de la GPU Adreno. |
| **Testing Automatizado** | **Recomendado** | Falta suite de pruebas unitarias automáticas con Vitest o Jest para verificar cálculos matemáticos y raycast. |
| **Manejo de Hand Tracking** | **Futuro** | Reservado para v0.3 cuando se diseñe el módulo de gestos espaciales. |
| **Física y Audio** | **Futuro** | Deben mantenerse estrictamente fuera del Core v0.1.0 y v0.2.0. |
